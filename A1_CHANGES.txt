SotF Client Probe  vA1  --  变更说明
==================================================

版本序列从 A1 重新开始（此前为 v2.40.3）。
从本版起，服务器端与客户端同步出包，除非定稿，否则不再单独发布一端。


一、新增：11008 链路（Link.cs）
----------------------------------------------------------------
· 服务器地址自动获取：从 BoltProbe 拿到 DS 的 IP（如 <SERVER_IP>:11005），
  换成 11008 端口。不需要在配置里手填。
· 握手策略（按约定）：
    - 最多 10 次探测，间隔 500ms
    - 单次失败等 1 秒再试
    - 10 次全失败 -> 显示 SERVER OFFLINE，客户端继续离线采集
· 离线模式不是"停止工作"：本地采集、HUD、jsonl 全部照常，
  只是不再向服务器同步。
· 线程安全：所有网络调用在后台线程，服务器不响应也不会卡帧。


二、新增：时钟对时
----------------------------------------------------------------
· Cristian 算法：offset = srv_utc_ms - (t0 + t1) / 2
· 多次探测取 RTT 最小的样本。
· 只记录 offset，不改本机时钟；两端各留各的时间戳，事后按 offset 对齐。
· 偏移每场都不同（实测 10.5s / 11.2s / 1.1s），必须每场重测。


三、新增：链路通讯日志
----------------------------------------------------------------
· 文件：probe_out/link_comm.txt
· 记录：握手开始、每次探测的成败与 RTT/offset、上报失败、异常。
· 用途：服务器端 11008 不通时，一眼看出是"连不上"还是"连上了但拒绝"。


四、新增：统一日志命名
----------------------------------------------------------------
· 格式：C_<登录时间>_<停止时间>.txt
  例：C_20260910_114455_20260910_115230.txt
· 服务器端对应 S_ 开头，同一规则，便于按场次配对。
· 内容含链路状态（Link.DiagText）与 steamid。


五、HUD 新增：链路状态行
----------------------------------------------------------------
· 握手结束后常驻显示：
    绿色  LINK OK  off=xxx ms  rtt=xxx ms
    红色  SERVER OFFLINE
· 位置在对时倒计时下方（对时窗口期间下移，不重叠）。
· SERVER OFFLINE 明确告知已降级离线，避免"以为在同步其实没有"。


六、新增：上报内容
----------------------------------------------------------------
每秒一批（后台线程），字段：
    cli_ms   客户端 epoch 毫秒
    ts_utc   UTC 时间字符串
    sid      SteamID64
    hp       当前血量
    dn       是否倒地
    p        坐标 [x,y,z]
服务器端读不到玩家血量、也没有 SteamID（专用服无 PlayerNetwork 类型），
这些只有客户端能补 —— 这正是"受害者归属"缺的那一半。


七、版本校验标记
----------------------------------------------------------------
· 版本号 "A1" 太短，在 DLL 二进制里随手就能撞上，不适合当判据。
· 部署脚本改查唯一标记串：SOTFPROBE-A1-MARK
· build 后看到  [OK] C. version A1 marker ... is inside the DLL  才算编对。


八、未做（不藏）
----------------------------------------------------------------
· 真机编译：沙盒无 .NET SDK，本包为源码 + 脚本，需在本机 build。
· 加密/签名：当前明码 HTTP，按约定后续再加。
  在加密之前，这批数据不能用于真实判定或封禁。


九、新增：在线交叉比对 CrossCheck.cs（A1 第二轮）
----------------------------------------------------------------
· 要解决的问题（实测）：服务器端记了 12 次 player_hit，玩家只真掉了 1 次血。
  其余 11 次服务器不知道打的是谁 —— 专用服上 victim_steamid 恒为 null，
  可能是 Kelvin / Virginia / 建筑，也可能是没掉血的弹反。
  所以"服务器端命中数"不是命中数，不配对就不能用。

· 配对三条件：
    1) 时间：用 Link 实测的 offset 把服务器端 ts 折算到客户端时钟
    2) 窗口：±1500ms 内取最近的一条本地命中
    3) 位置：两端都有坐标时必须在 5 米内
  第 3 条不是装饰。同一场里 raw 52.5 出现过 6 次，只靠时间 + 数值
  会配错行；位置是唯一能证明"就是这一下"的东西。

· 结果分类：
    real     配对成功 —— 玩家真掉了血
    phantom  服务器端记了，客户端没掉血 —— 打到别处 / 弹反无伤
    env      客户端掉了血，服务器端没有 —— 坠落、火烧等非怪物伤害
· 输出：
    HUD 一行   XCHK real=3 phantom=9 (75%)
    文件       probe_out/crosscheck_<时间>.txt（逐条明细）
    会话日志   xchk: 一行诊断

· 为什么放在客户端（临时）：目前只有客户端同时握有两端数据。
  配对函数是纯的 —— 输入两个 list，输出配对结果，不碰任何游戏对象 ——
  将来数据库服务器起来后整体搬过去即可，读上传的文件而不是本地内存。
  这是这一版刻意的设计约束，不是凑合。


十、本轮未做（不藏）
----------------------------------------------------------------
· 真机编译：沙盒无 .NET SDK，本包为源码 + 脚本，需在本机 build。
· 比对目前只做 player_hit。dodge / deceive / parried 等下一轮。
· 握手失败（SERVER OFFLINE）时比对不运行 —— 没有 offset 就无法折算时间。
  此时客户端仍离线采集，只是不产出比对结果。

 A1.05  (2026-09-10)  -- 修复 A1.02 编译失败
============================================================

[BUG] 客户端 A1.02 编译失败（这是 A1 系列第一个真实编译错误）

  报错（deploy_all.log，用户实机回传）：
    src\CrossCheck.cs(191,26): error CS0246:
      The type or namespace name 'Thread' could not be found
    src\Link.cs(220,18): warning CS0219:
      The variable 'online' is assigned but its value is never used

  原因：CrossCheck.cs 是 A1 新增文件，用了 new Thread(...) 开后台
        拉取线程，但没有 using System.Threading;。
        Link.cs 有这条 using，CrossCheck.cs 漏了。

  上一版我声称"外部依赖 TcpClient+Thread, using 齐全" -- 那句话
  是错的，我只核了 Link.cs，没核新写的 CrossCheck.cs。

修复：
  1. CrossCheck.cs  新增 using System.Threading;
  2. Link.cs        删除未使用的局部变量 online（消除 CS0219）

新增防线（防止同类问题再出现）：
  写了 using 缺失扫描器 -- 对每个 .cs 文件剥离注释与字符串后，
  按"命名空间 -> 常见类型"映射反查缺失的 using。
  用它回扫 A1.02 全部 28 个源文件，准确抓出了上面这个 Thread
  （与编译器报的行一致），另外 3 条为误报：
    BoltProbe.cs / ProbePlugin.cs 的 EndPoint  -> 是 BoltProbe 自定义
                                                  的 static string 字段
    Diag.cs 的 Group                            -> 是 Diag 自定义的
                                                  字段 Group
  扫描器不区分"用户自定义成员名"与"框架类型名"，故需人工确认。

其它：
  - 版本号 A1.02 -> A1.05（源码 BUILD_MARK、两个 bat 标题、
    install.ps1 注释、部署校验串全部同步）
  - 采集逻辑未改动

A1.05  (2026-09-10)
============================================================
FIX: 版本标记校验 C 行误报 MISSING。
  现象：A1.04 客户端编译部署全部成功，唯独 C 行报
        "version marker SOTFPROBE-A1.04-MARK NOT found inside the DLL"。
  根因：BUILD_MARK 声明为 const 且全代码未引用，只存在于元数据的
        Constant blob（UTF-16），不进入 #US 字符串堆；校验脚本用
        Unicode.GetString 从头解码整个文件做 Contains，一旦该串在文件
        中的字节偏移为奇数，解码即错位，必然搜不到。
        A1.04 新增 BEP_VERSION 常量后元数据布局位移，奇偶性翻转，
        于是 A1.03 能过、A1.04 过不了。
  修法（双保险）：
    1) BUILD_MARK 由 const 改为 public static readonly —— 字段初始化器
       会生成 ldstr，字符串必定落进 #US 堆，与实际是否被引用无关。
    2) 校验改为三路搜索：Unicode(偏移0) / Unicode(偏移1) / ASCII，
       不再受字节对齐影响。
  说明：C 行失败不影响功能。A1.04 的 DLL 本身是好的（BEP_VERSION
        已是纯数字、HUD 校验 D 通过），可以直接使用。
  另有：BEP_VERSION 1.4.0 -> 1.5.0。
