SotF 客户端探针 —— 两步走（必须按顺序）

  1. 1_setup.bat           →  清除 + 安装 + 提示你启动游戏一次
  2. 2_build_deploy.bat    →  编译 + 装进 plugins + 五项校验

两步都不能省，第 1 步后半段「启动游戏」尤其不能省。

────────────────────────────────────────────────────────
为什么要这么排（重要）
────────────────────────────────────────────────────────

以前是「清除 → 编译 → 部署」，结果踩了这个坑：

  游戏从来没启动过 → BepInEx\interop 目录不存在
      → 项目里 HAS_INTEROP 未定义
          → HudBand.cs（F1 十格横条）整段被编译跳过
              → 编译报 BUILD OK，但 DLL 里根本没有 HUD
                  → 进游戏按 F1，什么都没有

这不是代码 bug，是编译时机问题。interop 是游戏自己生成的，
必须先启动一次游戏才会有。所以「启动游戏」被塞进第 1 步的
最后，而第 2 步开头设了硬闸：

  interop 目录里程序集少于 50 个 → 直接拒绝编译

宁可报错，也不再产出一个「看起来成功、其实没有横条」的 DLL。

────────────────────────────────────────────────────────
每一步做什么
────────────────────────────────────────────────────────

第 1 步  1_setup.bat   （三部分：CLEAN / INSTALL / LAUNCH）

  PART 1/3  CLEAN
    删除  bin\  obj\                      上次编译产物
    删除  各种 build / install 旧日志      避免新旧日志混在一起
    删除  plugins\SotfClientProbe.dll      ← 旧版本残留的元凶
    归档  probe_out → probe_out_时间戳     历史数据保留，不删
    保留  sotf_stats.json                  累计死亡/时长，不重置
    同时  开启统一日志 deploy_all.log（跑第 1 步会清空重建）

  PART 2/3  INSTALL
    调 install.ps1，铺好 BepInEx：
      BepInEx\core、doorstop（winhttp.dll）、
      预置 Unity 基础库（避免启动期联网卡死）、改写 BepInEx.cfg
    判定方式看产物（BepInEx.Core.dll 在不在），不靠退出码

  PART 3/3  LAUNCH   ★不能省，需要你动手
    屏幕提示：启动游戏 → 在主菜单等几分钟 → 彻底退出 → 回来按键
    然后数 BepInEx\interop 里有多少个 dll（完整约 235 个）
    少于 50 个就报 FAIL，不让你进第 2 步

第 2 步  2_build_deploy.bat
    先查 interop（硬闸）→ 查 dotnet → 编译 → 覆盖 plugins → 校验：
      A 装进去的字节数 = 编译出来的字节数
      B 字节数 > 187904（旧的残留版本就是 187904）
      C DLL 内部能搜到版本串 2.40.0
      D DLL 内部能搜到 HUD 特征串 ON/SWITCH/OFF   ← 最关键
      E plugins 目录只有本探针（有其他插件本探针会自动失效）
    A~D 全过才打印 DEPLOY OK

────────────────────────────────────────────────────────
统一日志
────────────────────────────────────────────────────────

两步的所有输出都追加到同一个文件：

    deploy_all.log（在包目录里）

包括：每一步的消息、install.ps1 的完整输出、编译的完整输出、
五项校验结果。出问题只发这一个文件就够。

────────────────────────────────────────────────────────
窗口不会闪没了
────────────────────────────────────────────────────────

两个 bat 都做了「自重入」：真正干活的部分跑在子 cmd 里。
就算正文被语法错误打死，外面这个窗口也留着，打印退出码，
等你按键。不会再出现「黑框一闪、日志只写一半」的情况。

另外两个文件都刻意避开了三种会静默杀掉批处理的写法：
    dir | find /c /v ""          （v2.40.1 第 4 步死在这条语句上）
    setlocal EnableDelayedExpansion
    多行 ( ... ) 块里做 set

────────────────────────────────────────────────────────
装完之后在游戏里验证
────────────────────────────────────────────────────────

  BepInEx 控制台应打印：SotF Client Probe v2.40.0
  进服后屏幕顶部：30 秒倒计时 SYNCING CLOCK... 29（对时窗口）
  F1：横条开 / 换配色 / 关
  F9：重置累计死亡与游戏时长

如果 F1 还是没反应，先看 deploy_all.log 里 D 那一行，
再确认是不是 plugins 里有别的插件（E 项会警告）。
