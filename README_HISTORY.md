## v2.38.0 改了什么（相对 v2.36.0）

- **新增 `clock_anchor.txt`**：插件启动时写一份"本机本地时间 ↔ UTC"对应关系。
  服务器端 v3.28 带了 `ClockOffsetSec`（实测 10.503 秒），但那是**某一台机器上**
  测出来的时钟偏差，换机器就会变。有这个文件后，对账脚本能自己把两条时间轴
  换算到 UTC 再比，不必假设时区一致。
- **`client_digest.txt` 增加 `ts_utc`**：原来只有本地时间，跨平台比时间很别扭。
- 版本号 2.36.0 → 2.38.0。

其余逻辑未动。v2.36 的十格 HUD、F1 换页、三套配色、45 项 vitals、
真实掉血 `hp_loss`、会话摘要全部照旧。

# 以下为历史存档（v2.11 及更早）

验证客户端能否读到**真实血量**、**SteamID**、**当前服务器标识**，
并提供**背包内容监测**与**游戏内左上角 HUD**。
这几个结论决定"服务器 + 客户端 + 数据库"三组件架构是否成立。

## v2.11.0 改了什么（相对 v2.10.0）

### 新增 F2：单页轮询（2 秒自动轮播）

- **按 F2** → 打开 HUD 并从第 1 页开始，**每 2 秒自动切到下一页**，在
  总览 / 死亡 / 受击 / 速度 / 血量损失 / Logo 六页之间循环
- **再按 F2** → 停止轮询并**关闭 HUD**
- **按 F1** → 立即接管为手动模式（取消轮询），继续按 F1 逐页前进到关闭态

轮询只在这六页之间循环，不会落到"关闭"态——否则每轮都会闪一下黑屏。
Logo 页的 10 秒自动关闭在轮询期间**不生效**，交给 2 秒计时器接管。

### 现在一共有几张卡？

**6 个页面，共 9 张卡**：

| 页面 | 卡数 | 说明 |
|---|---|---|
| 1 总览 | **4 张** | DAMAGE TAKEN / HP LOST / DISTANCE / DEATH 横排，底部小字 STEAMID |
| 2 死亡 | 1 张 | `S - 03` |
| 3 受击 | 1 张 | 波形 |
| 4 速度 | 1 张 | 波形，顶部大字总距离（KM 三位小数） |
| 5 血量损失 | 1 张 | 阶梯折线 |
| 6 Logo | 1 张 | 10 秒自动关闭（手动模式下） |

尺寸：单页卡 **252×78**；总览 4 张各 **150×78**，横排总宽 612，加底部
STEAMID 一行共 93 高。全部**透明底**（v2.9 起绿网格底纹已移除）。

### 按键总览

| 键 | 行为 |
|---|---|
| F1 | 打开 / 逐页切换（6 页）/ 第 7 次关闭 |
| F2 | 开启 2 秒自动轮询 / 再按一次停止并关闭 |

**HUD 默认关闭**，进游戏不会自己弹出来；进服务器后需通过 30 秒采集门槛
才会显示任何内容。

## v2.10.0 改了什么（相对 v2.9.0）

### 1. 六项数据在下线后直接清零

玩家离开服务器（回主界面 / 掉线 / 退出对局）的那一刻，HUD 背后的六项数据
全部归零，而不是把上一个服务器的数字继续留在屏幕上。

清零前会先把这一局入库：`sessions.log` 与事件流都会写一条 `reason=offline`
的会话记录。所以清零不等于丢失 —— 只是不再 "live"。

| 数据项 | 清零方式 |
|---|---|
| 受击次数（DAMAGE TAKEN） | `Stats.Reset()` |
| 损失血量合计（HP LOSS） | `Stats.Reset()` |
| 行走距离（DISTANCE） | `Stats.Reset()` |
| 死亡累计（DEATH） | `DeathProbe.Reset()`（含 60 秒窗口） |
| 玩家坐标（实时） | `Stats.Reset()`（HavePos=false，显示 `--`） |
| STEAMID（当前） | 下线时 HUD 整体隐藏（Connected=false），不再显示旧值 |

### 2. 损失血量合计已在 HUD 中

这一项此前已在两处显示，本版确认保留，未做改动：

- 总览第二张卡 **HP LOST** —— 直接就是 `Stats.HpLoss` 累计值
- 独立「血量损失」页右上角 —— `XXX.X TOTAL`

### 3. 附带修正：30 秒门槛期间 HUD 不再"假装隐藏"

v2.9 的注释写着"leave the overlay hidden"，但 `Connected` 只被设成 true、
从未被设回 false。于是：上一个服务器开着 HUD，换服后 30 秒门槛期间，
HUD 仍然画在屏幕上（显示的是已清零的 0）。现在门槛期间与下线时
都会真正把 `Connected` 置回 false。

## v2.9.0 改了什么（相对 v2.8.1）

### 1. 不再出现黑色控制台窗口

`1_安装` / `2_编译` 现在提供 **`.vbs` 启动器**（双击 `.vbs`，不要双击 `.bat`）。
它以后台方式调用同名 bat，全程无窗口，结束后弹一个结果提示框，内容取自日志尾部。

| 文件 | 作用 |
|---|---|
| `2_编译.vbs` | 静默编译 + 部署，弹窗报告 BUILD OK / FAILED |
| `1_安装.vbs` | 静默安装 BepInEx 与依赖 |
| `2_编译.log` / `build_detail.log` | 完整过程与编译原始输出 |

`.bat` 仍然保留，双击它按老方式运行（有窗口、结束暂停），可作排障用。

### 2. 六个视图全部可达 + LOGO 修好

v2.8 里 F1 **一次按下被两条输入路径各处理一次**：`Update()` 轮询到一次，
`OnGUI` 的事件又处理一次，于是一次按键跳两格。只有偶数号视图能被看到，
LOGO（第 6 个）永远到不了。

修法两条：

- 220 ms 去抖，同一物理按键只算一次
- 一旦确认 `Update()` 路径可用，`OnGUI` 路径立即停止监听

### 3. HIT 卡改名 DAMAGE TAKEN

总览第一张卡与受击波形页的标题统一为 **DAMAGE TAKEN**。

### 4. 尺寸缩减 2/5，文字尺寸不变

| | v2.8 | v2.9 |
|---|---|---|
| 单页卡片 | 420×130 | **252×78** |
| 总览 | 420×410（四卡竖排） | **四卡横排，总高 78** |
| 字号 | — | **完全不变** |

卡片缩了，字没缩 —— 数字跟着卡片一起变小就看不清了，而"扫一眼就读出来"
是这个 HUD 唯一的价值。总览改横排后从占屏 410px 变成一条 78px 的横带。

### 5. 绿底网纹取消，改为透明

烘焙的绿色网格 + 扫描线底图已删除，不再缓存纹理。现在只画边框、曲线和文字，
其余直接透出游戏画面。坐标轴保留基线（读波形高度要用），中间的网格线一并去掉。

### 6. F1 增加"关闭"态 + 默认关闭

F1 现在有**第七个状态：关闭**。按到 LOGO 之后再按一次即关闭，再按从总览重新开始。
**HUD 默认是关闭的**，进游戏不会自己弹出来。

### 7. 进服务器 30 秒后才采集/显示

新增 `ArmDelayMs = 30000`：检测到服务器端点后，还要再等 30 秒才开始计数、写事件、
显示 HUD。这 30 秒是**采集门槛**，用来跳过落地、生成、血量初始化这段最脏的窗口
—— 之前那笔 80.9 的伪掉血就是在这个窗口里读到的。

门槛通过时写一条 `{"type":"armed"}` 事件，数据流里能看出采集从哪一刻开始。

### 8. 死亡 60 秒去重

60 秒内再次死亡**不重复计数**。这是死亡去重窗口，与上面 30 秒采集门槛是两件事。

- `deaths` — 去重后的数字（HUD 显示、评级用这个）
- `deaths_pre` — 未去重的原始事件数

两者同时写进数据流，差值即被窗口抑制的连锁死亡。`death_probe.txt` 按来源
（native / downed / health）分别列出 raw 与 windowed。

### 9. 换服务器时全部清零（含本地记录）

原来的判断是"是否见过端点"，只触发一次，所以在同一次游戏进程里换第二个服务器时，
受击/掉血/距离会从上一个服务器带过来。死亡看起来正常，只是因为游戏自己换档时
把计数器清零了。

现在改成"**端点是否变化**"：端点一变就重置全部计数器并重新计 30 秒门槛。
重置前把上一局汇总写进 `probe_out\sessions.log`（一行一个服务器），
退出游戏时也会补写最后一局。

### HUD 从六行文字改为六张图表，F1 切换

左上角，军绿终端风格。**F1 按一次换一个视图**，按到第六张后回到第一张。
（**v2.9 起：绿网格底纹已改为透明，尺寸 420×130 → 252×78，F1 增加第七态"关闭"**）

| F1 第几次 | 视图 | 尺寸 | 内容 |
|---|---|---|---|
| 1 | 总览 | 420×410 | 四张卡纵向堆叠：HITS / HP LOST / DISTANCE / DEATH，底部小字 STEAMID（**v2.9 起改为横排 252×78，见上**） |
| 2 | 死亡 | 420×130 | 标题 DEATH，中央大字 `S - 03`（评级 - 次数，同等大小） |
| 3 | 受击 | 420×130 | 波形：波峰越密=挨打得越频繁，峰高=该次伤害 |
| 4 | 速度 | 420×130 | 顶部大字总距离（KM，三位小数），波形为 KM/H，平缓段=停留 |
| 5 | 血量损失 | 420×130 | 累计损失折线，阶梯状上升 |
| 6 | Logo | 420×130 | 显示 10 秒后**自动关闭**，再按 F1 从总览重新开始 |

死亡评级分档：`0-5 S`（暗金）/ `6-10 A`（金）/ `11-20 B`（银）/ `21-30 C`（铜）/ `31-40 D` / `41-50 E` / `51+ F`（后三档白色）。评级字母的颜色就是该档颜色。

### 新增：时间序列（`Series.cs`）

原来的 HUD 只有累计值，画不出"什么时候发生的"。新增的 Series 记录三条历史：
每次受击的时刻与伤害、每个采样点的速度、每个采样点的累计失血。

- 点数上限 **200**，超出**按时间聚合**而不是截断——截断会丢掉会话末尾，
  而末尾通常正是要看的部分
- 速度聚合取**区间最大值**：一次 0.4 秒的冲刺不会被采样漏掉
- 累计量（失血）聚合取**区间末值**：阶梯只关心终点，不关心峰值

### 新增：移动速度与停留时长

速度 = 相邻采样的位移 ÷ 采样间隔，换算 KM/H。**只统计被采纳的位移**——
重生、传送那种瞬移不算跑动，否则一次重生能把纵轴撑到几百 KM/H，整张图就废了。

做了轻度平滑（0.5）：2Hz 原始速度抖动很大，按住 W 走路时相邻采样能差好几个 KM/H，
不平滑的曲线是噪声不是信息。平滑后真实"静止→冲刺"仍在约 1 秒内到顶。

低于 0.5 KM/H 计入停留时长，显示在速度视图右上角。

### 关于受击波形的高度

伤害值优先取被 hook 方法的第一个数值参数；取不到时**回退为"实际掉了多少血"**
（延迟一个采样周期补齐，因为掉血量要等下一次采样才知道）。

这是一处**未经确认的猜测**，只用于画图，不影响记录：被 hook 方法的参数布局
从未证实过（已知一次命中对得上服务器的 52.5，另一次对不上）。原始参数仍然
原样写进 `hit_event` 的 `args` 字段，供事后定性。

### Logo 视图

图片以**嵌入资源**方式编译进 DLL，不是旁边的散文件——重装或手工拷贝时
不会漏掉资源。解码通过反射调用 `ImageConversion.LoadImage`：该类型在独立的
模块里，硬引用会让整个项目在缺少该模块时编译失败，反射则会降级为文字显示。

原图 1280×720，按 420:130 居中裁切（保留书法字与右上印章），原图本身是透明底，
无需去背。

### 采样记录字段无变化

`client_*.jsonl` 的字段与 v2.7 完全一致（hits / hp_loss / dist / deaths /
deaths_src / server / conn 等）。图表只是已有数据的另一种呈现，没有新增采集项。

### 已知限制

- **F1 生效依赖游戏把按键传给 Unity**。默认走 `Update` 轮询，失败 3 次后自动
  切换到 OnGUI 的按键事件；如果游戏吞掉了 F1（极少见），两张路径都不通，
  图表就停在总览。
- **总高度 420×410 是按 1080p 定的**。2K/4K 下显得小，1440×900 以下会偏高——
  目前是固定像素，不随分辨率缩放。
- 单局内切换服务器会清空全部序列（与 v2.7 的计数重置同步）。

## v2.7.0 改了什么（相对 v2.6.0）

### 新增：HUD 第六行 —— 死亡累计

```
受击次数【合计】 12
损失血量【合计】 128.4
行走距离【合计】 342.7
死亡累计【合计】 1
玩家坐标【实时】 214.7, 13.9, 1497.5
STEAMID【当前】  <YOUR_STEAMID64>
```

新增文件 `DeathProbe.cs`。

**优先读游戏自己的计数器，而不是靠掉血推断。**
235 个 interop 程序集里查到（实测，非猜测）：

```
PlayerStats.get__playerDeathCount  -> System.Int32     ← 权威计数
PlayerStats.get_PlayerIsDowned     -> System.Boolean
PlayerStats.IsDead                 -> System.Boolean
```

这一点很关键：本作玩家被击倒通常是 **DOWNED（倒地）而不是血量归零**，
任何"血量低于 X 就算死"的阈值都是猜的——正是 176 和
`is_parrying` 那类错误的成因。所以直接取游戏已经算好的数字。

**三个来源同时跑，只显示优先级最高的**，全部写进 `death_probe.txt`：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | `_playerDeathCount` | 游戏权威计数，显示为**增量**（见下） |
| 2 | `PlayerIsDowned` 边沿 | false → true 记一次 |
| 3 | 血量归零边沿 | 兜底；本作很可能永远不触发 |

**为什么是增量**：`_playerDeathCount` 在插件挂载时可能已经不是 0
（此前死过、或跨局残留）。直接显示会把别人的账算进来。
所以首次读数作为基线，HUD 显示 `当前 - 基线`；
原始值和基线都写进报告，不隐藏。

**三个数怎么对照着看**（`death_probe.txt` 里也写了）：

```
native 与 downed 一致        → 计数器可信
native 不动、downed 在涨     → _playerDeathCount 不是本局的，改用 downed
health 恒为 0 而另两个在涨   → 正常：本作是倒地机制，不是血量归零
```

**读不到时显示 `--` 而不是 0。** 屏幕上的 0 无法区分
"确实没死"和"计数器没读到"，而这两种情况的处理方式完全不同。

### 采样记录新增字段

`deaths`（读不到时为 `null`）、`deaths_src`（`native`/`downed`/`health`）、
`deaths_raw`、`deaths_base`。带来源后，0 才有意义。

### 计数起点改为"连上服务器的那一刻"

以前计数从插件加载就开始累积，主菜单期间也在算。
现在改为**首次拿到服务器地址时重置**所有计数（含死亡基线）——
这也正是 HUD 开始显示的时机，两者语义对齐。

## v2.6.0 改了什么（相对 v2.5.0）

### 新增：左上角 HUD（进服后显示，每秒刷新）

```
受击次数【合计】 12
损失血量【合计】 128.4
行走距离【合计】 342.7
死亡累计【合计】 1
玩家坐标【实时】 214.7, 13.9, 1497.5
STEAMID【当前】  <YOUR_STEAMID64>
```

新增两个文件：`Stats.cs`（计数）、`Hud.cs`（绘制）。

**三个数字，三种口径**（这是刻意的，不是偷懒）：

| 项 | 来源 | 说明 |
|---|---|---|
| 受击次数 | 伤害钩子 | **不是**由掉血推出来的。被格挡/被护甲吸收的命中本来就不掉血，纯靠掉血统计会漏掉它们 |
| 损失血量 | 血量差值累加 | 与"受到的伤害"不是一回事：30 点伤害被护甲吃成 2.7 点掉血，HUD 显示的是玩家血条上真实少掉的 2.7 |
| 行走距离 | 坐标积分 | 超过阈值的跳变（重生、传送、过场）不计入，否则一局能走出几公里 |

**防重复计数**：插件同时 patch 了 `VailActor.ReceivedDamage` 和
`PlayerStats.OnNetworkHit`，一次命中可能触发两个钩子。
200ms 内重复的第二次会被吞掉。

**中文字形是个真问题**（不是画不出来，是画成空白方块）：
IMGUI 内置字体是 Latin 字体，**没有中文字符**。
所以代码会用 `Font.CreateDynamicFontFromOSFont` 载入系统中文字体
（微软雅黑 → 黑体 → 等线 → 宋体 → 楷体）。
**如果全部载入失败，标签自动降级为英文**（HITS / HP LOST / DIST(m) / POS），
保证数字仍然可读，而不是一片方块。

### 采样记录新增三个字段

`hits`、`hp_loss`、`dist` —— 与 HUD 显示的是同一组数字，
可以直接拿 HUD 截图和 jsonl 对账。（v2.7 另加 `deaths` 系列，见上）

### 配置（游戏目录 `BepInEx\config\sotf.clientprobe.cfg`）

| 键 | 默认 | 说明 |
|---|---|---|
| `Hud.Enabled` | true | 关掉则不绘制 |
| `Hud.RequireServer` | true | 只在拿到服务器地址后显示（即进服后） |
| `Hud.FontSize` | 16 | 字号 |
| `Hud.RefreshMs` | 1000 | 文字刷新间隔；绘制本身跟帧率走 |

### 已知限制

- **HUD 需要 ClassInjector 路由**（注入自己的 MonoBehaviour 才有
  `OnGUI`）。日志里 `frame hook: ClassInjector` 表示可用。
  若退回 Harmony 兜底路由，HUD 不会显示——这一点会在日志里说明。

- **背包监测仍未取到实际物品**：`GetAllItems()` 这个 API 已确认存在

## v2.5.0 改了什么（相对 v2.4.1）

### 1. 服务器标识改为从 Bolt 读（新增 `BoltProbe.cs`）

v2.4.1 用进程 UDP 表找远端地址，**这条路物理上走不通**：
Photon Bolt 用的是**无连接** socket，操作系统 UDP 表里没有它的远端
对端。上一局 2050 条采样的 `server` 字段**全部为空**，正是这个原因。

游戏自己的日志其实已经把答案打出来了：

```
This client connected to server (bolt):
    [Connection [EndPoint <SERVER_IP>:11005 | 7483222601876122365]]
```

所以数据在进程里。v2.5 直接从 Bolt 的连接对象上读（均已对照
interop 程序集确认存在）：

| 成员 | 值 |
|---|---|
| `BoltNetwork.Server` | 服务器连接对象 |
| `BoltConnection.RemoteEndPoint` | `<SERVER_IP>:11005` ← **地址端口为主键** |
| `BoltConnection.ConnectionId` | `7483222601876122365` |

诊断写入 `bolt_probe.txt`。读不到时每条采样仍会带空 `server`，
不会误判成"没有连服务器"。

### 2. 血量改为事件驱动（新增 `DamageHook.cs`）

2Hz 轮询的**读数是准的**（与存档记录的 90.67428 相差 0.09，
按 1.00 HP/秒 回血速率约合 0.09 秒采样时差），但它无法回答
**"伤害是什么时候落下的"**：两次采样之间可以掉血又被回血补回，
采样器只看到一条平线。上一局 16 次服务器端命中里有 8 次在客户端
完全看不到变化。

不靠提高采样率解决，而是 patch 游戏自己的伤害入口，在它触发的
**那一刻**读一次血量：

```
Sons.Ai.Vail.VailActor.ReceivedDamage(...)   任何 actor 受伤
PlayerStats.OnNetworkHit(...)                本地玩家，来自网络
```

**钩子只当触发器，不解析伤害数值**——参数布局随游戏版本变化，
赌它就是 `is_parrying` 当初读成"永远 false"的同一类错误。
前 8 次命中会把参数类型与取值原样记进 `args` 字段，供事后确认
伤害在哪个位置。

输出为 `hit_event` 事件（带 `hp`、`is_local`、时间戳）。
**被护甲吸收的命中本来就不掉血**，所以 `hit_event` 里血量没变
是真实观测，不是故障。

patch 结果与失败原因写入 `damage_hook.txt`。装不上也不影响轮询采样。

### 3. 背包诊断修复（真 bug）

上一局背包监测**输出 0 条**，而且没有任何诊断。原因是：

```csharp
if (!string.IsNullOrEmpty(inv))        // 只有"发生变化"才进
{
    ...
    Out.WriteReport("inventory_probe.txt", ...);   // 报告也写在这里面
}
```

容器成员找不到时 `Sample()` 永远返回 null，于是**最能说明为什么
找不到**的那份报告，恰好永远不会写出来。

现在报告无条件写出一次，`inventory_probe.txt` 里会列出背包对象
上所有可枚举成员及元素类型，下一版据此确定正确的容器名。

## v2.4.1 改了什么（相对 v2.4）

- 修复 CS0165 编译错误：`float hp;` 在 `Resolved && Sample(out hp)` 的
  `&&` 短路中赋值，编译器无法证明未解析分支上 hp 已被写入。

## v2.4 改了什么（相对 v2.3）

v2.3 在真机上跑通了编译与加载，但探测结果写着 `vitals: NOT FOUND`。
比对 interop 类型清单后确认：**不是游戏里没有血量，是我们自己的两处
代码把它挡在了门外。**

### 1. 类型名写错了

```
我们写的：Sons.Vitals
实际导出：Vitals          ← 没有命名空间
```

精确匹配永远命中不了，于是退化成关键词海选，而海选又被下面第二条
卡住。现在按 `Vitals` 直接命中，满分优先。

### 2. 候选列表在排序之前就被截断

```csharp
if (ScoreType(fn) > 0 && candidates.Count < 40)
    candidates.Add(t);      // 40 个坑在遍历途中就被低分类型占满
```

`Sons.dll` 排得靠后，轮到它时名额已经用完，排序根本来不及发生。
结果候选里全是 score 10~30 的杂项（`PlayerState`、`SetTreeHealth`…），
没有一个能读血量。

现在改成**全量收集 → 排序 → 再截断**。

### 3. 血量没读到时，坐标也被一起扔掉了

```csharp
if (!VitalsProbe.Resolved) return;   // v2.4 已删除
```

这一行导致：只要血量没探到，**整局的位置采样一条都不写**。
而位置恰恰是唯一能和服务器端互相印证的东西——
服务器端 `player_hit` 每次都带 `player_pos`，实测 16/16 命中。

**我们把最有用的证据自己扔了。**
现在血量与坐标独立采集，谁成了都不白跑。

### 4. 探测只跑一次，而且跑得太早

探测在插件加载那一刻执行，那时游戏还在主菜单，**角色根本不存在**。
失败后也不再尝试，于是一整局都停在 NOT FOUND。

现在未解析时会持续重试（带节流），进服后自然会对上。

### 5. 新增：背包内容监测

记录背包内容与数量变化。**只在真的发生变动时写记录**，
挂机不产生任何流量。

### 6. 新增：LocalPlayer 直连入口

不再满世界海选类型，改走游戏自带的本地玩家入口，
血量、背包、坐标三样都从那里取。搜索降级为备用路径。

## 顺序（不能乱）

```
① 双击 1_安装.bat
② 启动一次游戏，进主菜单后退出   ← 生成 interop，必需
③ 双击 2_编译.bat

```

**② 和 ③ 反了会出问题**：没有 interop 时会退回 Harmony 兜底路径，
那依赖"游戏类型按名字存在"，正是我们要避开的赌法。

找不到游戏目录时手动指定：

```
1_安装.bat -GameDir "D:\Steam\steamapps\common\Sons of the Forest"
2_编译.bat -GameDir "D:\Steam\steamapps\common\Sons of the Forest"
```

## 常见失败：Microsoft.Extensions 依赖缺失

症状（游戏启动日志）：

```
FileNotFoundException: Microsoft.Extensions.Logging.Abstractions, Version=6.0.0.0
   at BepInEx.Unity.IL2CPP.Il2CppInteropManager.Initialize()
```

原因：BepInEx core 依赖它，但**纯净的 .NET shared framework 里没有**，
官方 BepInExPack 自带的 dotnet 才有。`1_安装.bat` 会按四级来源自动补齐：

1. 包内 `offline\dotnet_deps`（手动投放位）
2. 专用服务器目录（最完整）
3. **本机 ASP.NET Core 共享框架**（装了 .NET SDK 就有）
4. NuGet 缓存 → NuGet 下载

都失败时，手动执行这三行（PowerShell）：

```powershell
$asp = "C:\Program Files\dotnet\shared\Microsoft.AspNetCore.App"
$src = (Get-ChildItem $asp -Directory | Sort-Object Name -Descending | Select-Object -First 1).FullName
Copy-Item "$src\Microsoft.Extensions.*.dll" "游戏目录\dotnet" -Force
```

然后重跑 `1_安装.bat`。

> 备用方案：下载官方 BepInExPack_IL2CPP（34 MB）解压覆盖游戏目录，
> 它自带的 dotnet 是完整的，一步解决。

## 判读结果


或者角色还没生成（主菜单阶段本来就没有角色）。

## 反作弊

- **致命级（立即自毁）**：plugins 目录有别的 DLL、其他加载器、作弊进程
- **观察级（仅记录）**：进程内陌生非系统模块

观察级故意不做成致命——Discord overlay、NVIDIA 驱动、微星小飞机都会注入 DLL，
当违规处理会误伤正常玩家。

客户端自检原理上都可绕过（改名、加壳）。真正兜底在服务器端：
那里记的原始伤害客户端改不了。

## 配套：服务器端 v3.25.0

服务器端已升级到 v3.25.0（瘦身版）：按"服务器端只留服务器端独有的东西"
